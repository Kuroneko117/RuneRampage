# 玩法独立复盘：本轮可修复的确定性断点

日期：2026-10-28。审查基线：`6a5dd6c`，分支 `codex/player-squash-motion`；Cocos Creator 3.8.8 / TypeScript，微信竖屏竞技场 Roguelite。只写本报告，没有改工程、素材或配置，没有操作共享 Cocos/浏览器，没有提交或发布。

## 方向与证据边界

保留术士自动施法、走位生存、主动过载、25 秒波次、波间四卡选装、20 波生存胜利的玩家幻想和循环。输入仍是单手拖动移动和主动过载；死亡/重新开始沿用现有流程。首分钟仍是两轮完整战斗和商店选择，再进入第三波；本轮只减少出生伤害与无效决策，不增加系统、怪物种类或内容量。

已读 `ArenaModel.ts`、`Balance.ts`、`Equipment.ts`、`CombatProfiles.ts`，以及 `GAME_EVALUATION_2026-10-21.md`、`SHOP_ANIMATION_FIX_REPORT.md`、`PLAYER_SQUASH_MOTION_REPORT.md` 和现有模型测试。旧报告已有不同随机开局结果，不能据此断言某装备强弱或直接重写难度曲线。

本次证据为原代码的独立纯模型执行：Node 加载 Cocos 随附 TypeScript，通过 `transpileModule` 转 CommonJS、VM 内存加载模块，直接调用模型夹具；未生成替代构建，也未访问共享预览。这些是逻辑缺陷复现，**没有新增运行截图、自然通关、手机性能或微信真机证据**。夹具给金币、固定怪物/时钟以隔离条件，不能用作自然局平衡统计。

## 按优先级排序的四项发现

### P1 / G1：Boss 在最近边界生成，贴墙玩家当帧直接掉血

- **位置**：`ArenaModel.ts:617–620` 从玩家到四条边的最短距离选边，Boss 坐标由玩家位置投影到该边；`258` 在第 10 秒生成；`297–299` 同帧执行接触伤害。
- **观察**：模型重置后设第 5 波、`waveTime=9.99`、`spawnClock=attackClock=999`，分别把玩家放到 `(-702,0)`、`(702,0)`、`(0,-1062)`、`(0,1062)`，执行 `step(1/60,0,0)`。四例均 `hp:5→4`。生成时中心距约 34，小于 `Boss.radius52 + playerRadius18 =70`；接触后的 40 单位推开使输出终态距离变为74，不能误读为生成安全。
- **玩家影响**：正常贴墙躲群怪时，Boss 进场就扣一血。地面符文虽有 1.1 秒预警，这次伤害来自即时身体重叠，玩家看不到对应的躲避窗口。
- **小范围修复**：保留场地边缘出生，但从边缘候选点中选择距离玩家足够远的安全点；同时留出原生可视预警/接近距离，不改 Boss HP、奖励、速度、10 秒进场或25秒结束。安全距离属于本轮设计选择，至少必须严格大于两者碰撞半径之和，优先沿用原怪物进场安全裕量。
- **验收**：四边及四角、中心分别测试；生成当帧无身体接触伤害，Boss 仍在合法边界内且最终会接近玩家；之后主动碰撞仍扣血，符文和冲刺仍有伤害；第5/10/15/20波均只生成一次。20波计时生存胜利和击杀附加成就不变。

### P1 / G2：商店有可负担装备却可能四格都不能买

- **位置**：`ArenaModel.ts:175–188`。`181` 注释称新商店首格提供可负担普通购入，但 `182` 完全随机选择 `level<5` 候选，没有查金币、持有状态或价格。`95` 普通首次刷新20币。
- **观察**：`random=()=>0`；金币20；`twin/blast/crystal/watch` 各Lv1，其他装备Lv0；调用普通 `enterShop()`。四格分别为 `twin Lv2 /50`、`blast Lv3 /153`、`crystal Lv3 /153`、`watch Lv3 /153`。可负担数0，而未持有的 `pierce` 仅10币（其他未持有装备也有12/20币）。刷新将吃掉全部20币。
- **玩家影响**：波间本应把这一波收入转成可见成长；玩家手里有购买力却只能离开或赌掉钱刷新。稀有卡连升价格会进一步让早期卡位看起来“全都买不起”。这不等于所有空商店都是bug：全部剩余升级都比金币贵时，本就允许储蓄。
- **小范围修复**：普通首次进店时，如果存在可负担的普通新购/升级，首个可用格从该集合选择普通商品；优先未持有装备以兑现现有注释。其余格保留随机稀有概率、非重复、最高Lv5和原价。Boss商店要同时保留稀有保证，不能让“首格普通”抹掉Boss奖励；可把稀有保证放后续可用格。若没有任何可负担普通候选，不降价、不送币，照常生成。
- **验收**：上述20币夹具至少出现一格可买；资金不足所有剩余装备时无赠送；仅1个未满装备、全满装备、Boss奖励商店、稀有连升、购买扣费/售出不能重复买、刷新计费、下一波清卡均保留。普通刷新是否同样保底须由工程记录决定，不能无意把新店保底扩成每次付费刷新都定向出货。

### P2 / G3：满级爆裂的连锁搜索固定偏向世界右侧

- **位置**：`ArenaModel.ts:429–431`，以 `nearest(explosion.x + explosion.radius, explosion.y, explosion.radius*2)` 寻找连锁对象。
- **观察**：`blast=5`，原爆炸中心(0,0)、半径100、伤害10，唯一存活敌人分别放在(-150,0)和(150,0)，HP100、`random=.99`。执行 `updateExplosions(.01)`：左右目标都不在原爆炸内，HP都仍100；左侧待发连锁0，右侧出现中心(150,0)、半径70的衰减连锁1。两例仅水平镜像，却得到不同触发结果。
- **玩家影响**：升级文案“一次扩散连锁爆炸”没有方向条件；向左清群时同样间距的敌人不接链，向右却接链，构筑效果难以学习和预测。
- **小范围修复**：搜索以原爆炸中心为圆心，保持现有2r搜索半径、伤害/范围衰减、一次链及对象池/特效上限。不要借机增加多目标链或递归。
- **验收**：水平镜像、垂直镜像四方向(±150,0)/(0,±150)均可触发一条链；超出2r范围不触发；链仍在0.16秒后结算，半径0.7倍、伤害0.5倍；子链不再递归，16个待爆池上限和80弹/96怪预算保留。

### P2 / G4：燃烧最后一跳击杀漏掉传火/火爆

- **位置**：`ArenaModel.ts:291` 先扣 `enemy.burn` 再执行燃烧伤害；`465–469` 死亡传火/火爆检查 `enemy.burn>0`，未识别此次击杀来自燃烧。
- **观察**：`flame=5`，隔离攻击/刷怪；目标HP12、燃烧剩余4秒、`burnClock=.5`、`burnDamage=1.5`，邻怪距50、HP100；固定60Hz推进。第241步（4.0167秒）目标被第8跳烧到HP0，`burn=-.0166667`，邻怪`burn=0`，待发火爆0。另做单步对照：目标HP1、`burnClock=.01`、燃烧伤害2；`burn=.01`时不传火/火爆，`burn=.2`时同次死亡正常传火并生成火爆1。
- **玩家影响**：Lv4“燃烧死亡后传火”、Lv5“燃烧死亡引发火爆”在最后一跳恰好致死时失效；不应由浮点余量或剩余一帧决定构筑效果是否兑现。
- **小范围修复**：在结算该跳伤害时保留本跳仍属燃烧的状态，或显式携带燃烧伤害来源；然后才处理到期。保持总跳数/每跳伤害和半秒频率，避免顺手延长燃烧或把已过期的普通击杀算传火。
- **验收**：最后一跳致死时Lv4传火、Lv5传火加一次火爆；非末跳致死原行为保留；最后一跳未致死后，燃烧结束再被普通弹击杀不传火；Lv0–3不解锁高级效果；4秒/60Hz案例不得额外多出第9跳。

## 实施与复验切片

建议先修G1/G2/G3，它们分别是可读威胁、公平商店决策、装备效果一致性；G4改动亦小，可独立安排。验收先以旧模型运行上述断言失败，再修复通过；必须回归25秒截止、Boss奖励只一次、20波生存即可胜利、死亡/重开和池上限。然后由工程/QA在实际Cocos预览查看Boss边缘进场和商店四卡，不能用本报告的模型输出宣布视觉完成。

此前报告的“前三波空闲、随机路线体验差异、过载频率”仍是需固定种子多路线样本验证的假设。本轮不建议据此加血加速加怪。`rareRefreshPending`在Boss首次稀有出货后即清除、免费刷新分支通常不生效，但目前没有可靠设计文档承诺应另送一次免费刷新，故未列为缺陷，不擅自增加经济奖励。
