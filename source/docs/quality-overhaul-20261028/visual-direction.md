## 配色、材质、边缘、光照

| 角色 | 建议色值 | 使用规则 |
|---|---|---|
| 深背景 | `#0A0E1B` | 空白、边缘、遮罩；使世界与 UI 连续 |
| 面板 | `#171D30` | 暗石/墨蓝单色面；不叠模糊或渐变玻璃 |
| 面板边 | `#43506F` | 次级工具与容器；一根主边+有限内边，不每层再套框 |
| 主文字 | `#EEEAE2` | 名称、关键数值、按钮动作 |
| 商品效果 | `#CBD2DF` | 高于当前 muted 的亮度；效果是购买依据，不能当脚注 |
| 次级文字 | `#9BA4BB` | 次要等级/说明；不用于主要收益和禁用价格 |
| 玩家/继续 | `#71EBDD` | 继续、就绪、主动确认；限制在一个主操作焦点 |
| 价格/购入 | `#E7C16F` | 金币、可购价格面、成功短闪；不与危险争高亮 |
| 稀有 | `#B49BFF` | 稀有角标、短边/等级。避免整张紫填色 |
| 受伤/快速敌 | `#FF7284` | 生命危机、快速怪暖色局部；不要拿作普通商品装饰 |
| 敌方危险 | `#FF4FA1` + `#FFE0F2` | 专用于敌弹、预警；深阴影边 `#140A1E` 保证跨地图可见 |

如工程已定义更明确的 fast/ranged/elite token，可采用其等价色，但各角色需保持稳定，不在一段动画内反复变调。原角色贴图不全局改色；敌人轻染色保留面部/甲壳明暗，形状标记补足色盲条件。

材质规则：战场用石材、布料与金属的小像素高光；UI 用暗石切角、细符文刻线和暖金价格片。边缘保持像素台阶与克制的 1–2 设计像素层次；按钮立面比容器亮，容器不反复用粗边。切角和原皮肤继承项目语言，不引入圆润后台卡片、网页侧栏或大面积发光。

光照/视角：角色继续轻俯视三分之四正面；地面符文保持透视压扁，不让角色、怪物与 UI 图标各自换视角。沿用既有像素高光方向，不新增照片纹理、绘画式柔焦或大块 bloom。地图 tint 先小步降低对比，不改原图身份；普通地面最高亮纹样应低于敌人轮廓与主体脸部。

## 字体与文字

复用现有 `assets/resources/fonts/RuneSans.ttf`，现查为 137,540 字节。`docs/UI_V08_ASSETS.md` 记录为 Noto Sans SC 字重 500 子集、修改家族名 Rune Sans UI；附带 OFL.txt。原许可文本和来源保持随包分发，不为本轮引入新字体。先前审计记录 547 glyph、missing=[]，只证明那次文案；新文案必须重跑覆盖检查，不能冒称当前新增汉字已验证。

| 角色 | 720×1280设计单位 | 393宽预计显示 |
|---|---:|---:|
| 首页标题 | 66–72 | 35–38 px |
| 页面/商店标题 | 40 | 21 px |
| 主操作 | 30–32 | 16–17 px |
| 商品名 | 30 | 16 px |
| 商品效果 | 26 | 14 px |
| 价格/金币 | 28–30 | 15–16 px |
| 等级/次说明 | 22–24 | 12–13 px |

上表估算基于横向缩放约 0.53，真机安全区和短屏 fit 会使比例更低；320×568 时优先保持主动作与收益可读，不继续无限缩字。长收益最多两行，禁止 `SHRINK` 悄悄缩小；明确换行或使用准确短句。“20°内轻微修正，保留散射”可改为“弹道修正 20°\n保留散射”，不改实际数值与效果。“攻击速度 +22%”“额外 1 发魔法弹”“法术伤害 +0.75”属于应直接保留的短收益。

## 商店：原四卡的具体规格

坐标以画布中心为原点、y 向上。下面为建议上限，工程需计算文字框与触控框的实际碰撞；不能只看面板外观未重叠。

| 元素 | 中心 / 尺寸 | 说明 |
|---|---|---|
| 标题 | y570、字号40 | 短标题“魔法商店”；波次信息弱一级并入小字，避免长标题拥挤 |
| 金币/生命 | 左上 y492、字号30/24 | 金币突出；无需每屏重复长说明 |
| 当前属性 | 右上 x240/y522、触控至少112×104 | 避开第一行卡顶；实际字面可小于触控面 |
| 商品卡 | x±161、y265/-77、306×320 | 四卡间横距16，纵距22；不横向滚动 |
| 图标 | 64×64 | 比原42明显扩大；可放顶部左侧，保留贴图原样 |
| 名称 | 字号30、可用宽至少180 | 四字名称不换行；位置让图标与名称互不遮挡 |
| 等级 | 字号22–24 | “Lv0 → 1”；普通无需每卡重复“普通”，稀有用单一角标 |
| 效果 | 字号26、行高30、最多两行 | 近白色；是卡片中主要信息，不灰到像禁用 |
| 购买 | 字面至少266×90、触控266×132、字号28 | 动作与价格同时显示，如“购买 · 8”；金币图标不代替价格数字 |
| 刷新/本局强化 | y-330，触控高132 | 降低边框亮度和填色；不得与第二行卡或购买触控相交 |
| 反馈/特殊行动 | y-422 附近、仅需时显示 | 不再常驻解释句；特殊行动和反馈各有明确空间，避免覆盖继续触控区 |
| 继续下一波 | y-536，600×132，字面104高 | 唯一大青色实心主操作，底部锚定在安全区内 |

卡片材料层级：暗容器 → 明亮商品图标 → 近白名称/收益 → 暖金购买面；不在名字、等级、效果后分别加框。买得起时金边和暖深色实体按钮；价格用暖金。不能把整张商品卡处理成按钮而丢掉明确购买按钮。

状态：normal 显示名称、等级变化、收益、价格；pressed 用 0.974–0.98 缩放/下移与亮边，约100ms；disabled 保留可读价格并显示“不足”，失去金色实心面；purchased 用勾/“已购买”与稳定暗面，不重复闪动；rare 增加小角标与紫色短边；success 暖金/青色短亮约300–480ms并立刻更新金币与等级；failure 文字原因+短红边，不全屏红闪；loading 文案明确、阻止重复购买；focus 用额外内线或角标，不能只改变颜色。手机无 hover 也须看出按钮。

## 主菜单和 HUD

首页：保留中央术士和稀疏法阵。主角显示画布高约176–200，维持原头身与持杖姿势；标题与开始按钮各占一个清楚层级。开始按钮600×104以上、字号32；模式/纪录仍为第二级。图鉴/分享/说明/音效保持至少88设计单位触控高，但可用较低字面高、暗边或符文工具样式，不能六个按钮全刷亮色。英文角标、角色说明、页脚和版本字减量。任何入口移动都要保留原功能和退回路径。

HUD：原布局的血量与波次在左、金币与倒计时在右可以保留。生命字号28–30、数字/倒计时28，波次24；血条更粗但无需厚容器；暂停至少88×88触控区，安全区内独立。底部保留过载晶体与“过载/就绪/冷却 Ns”，充能条与状态对齐，删除常驻操作说明或只在首局短暂出现。Boss 血条不和顶部信息、告示形成三段同权标题；Boss 名只显示一次，阶段说明短暂出现。

HUD调整先不改 `PRODUCT.ui.battleTop/battleBottom` 或镜头；本轮目标是消除冗余视觉，再通过同场景截图评估。改变战场视野会影响遇敌信息量，应作为单独可验证决定。

## 怪物、玩家与反馈生产规格

| 家族 | 保留项 | 改善目标 / 技术要求 |
|---|---|---|
| 玩家 | 80×88画布、既有pivot/角色身份、runtime112 | 银发脸和紫帽金边保持；地面符文低alpha；不扩大碰撞或新增整身光晕 |
| 普通怪 | 现图集、各自画布/pivot、行走序列 | 核对圆团/双翼/角/甲壳外形；动画缩放不超过原有体积语言；同屏原生尺寸审查 |
| 快速怪 | 当前imp/蝙蝠等外形 | 暖色轻染+短尖形标记，显示在身体上方；不同于圆形金币与友方星点 |
| 远程怪 | 兜帽法师轮廓、瞄准线 | 远程标记为窄菱/瞄准符；完整显露蓄力到发射方向，不依赖紫色本体 |
| 精英 | 宽肩守卫、现1.4倍率 | 金色短冠/双短角，不做金色全身平涂；避免与价格/金币外形混淆 |
| Boss | 128×104阶段画布、现2.4倍率 | 阶段主体轮廓递增，预警永远高于地面；不按单帧alpha bbox重新缩放 |
| 场地 | 720×1280原贴图、装饰、世界尺度 | 冷灰暗化对比，装饰不比怪物亮；不重复下载新场景 |
| UI皮肤 | 现64×32九宫格，两个32×32源块 | 同一切角/边线家族；保持约12 inset；不拉伸角部或混入独立网页圆角 |
| 图标 | 图集既有装备/金币/晶体 | 商品显示64×64；保持原比例、nearest像素边；文本不烘焙进图片 |

以上主要为运行时 tint、布局、shape/短文案变更，优先零新增位图。生产若必须新增敌人标记，使用共享Cocos矢量几何或同小图集，保留编辑源；不得每只怪每帧创建新 Graphics/SpriteFrame。任何新增文件记录来源、尺寸、pivot、状态、压缩与许可。既有角色/地图来源权利沿用项目清单，未经本次重新授权不冒称权利审查完成。

伤害数字：普通22–24，暴击28–30；减少“暴击/爆裂/OVERLOAD”等宽前缀，过载文字优先进入短状态提示。普通寿命建议0.45–0.60秒；附近有危险时不超过4组，玩家附近避免跨越主体。金币继续落在actor下层、低亮、减少飞行动画，不让奖励像敌弹。敌弹保留粉色箭头+浅边+深边；预警圆环要在灰度下也辨认边界与倒计时，不能只靠颜色辨别。

## 验收与交接

工程依次落实主题 token → 商店四卡与状态 → 首页/HUD层级 → 敌人颜色覆盖修复及危险层级；不改玩法数值。Producer仅在现有皮肤无法表达状态时补最小素材，不启动整组新角色生产。

1. 393×852、360×800、320×568、412×915 与含胶囊/刘海/底部手势区条件：四商品名称、两行收益、价格、购买和继续完整可读；触控框>=44 CSS px，推荐48；互不重叠，不能用字面大小代替触控测量。
2. 商店必须实际展示可购、不足、已购、稀有、刷新后、满级/强化、Boss祝福状态；购买一次只扣一次，卡片与金币同步，反馈不压按钮。以真实购买结果截图验收。
3. 首页开始入口首眼可见，次级功能不抢主操作；图鉴/分享/设置/说明仍可达，返回路径完整。只换边框颜色不足以算完成层级改善。
4. 战斗分别拍普通、快速+远程+精英混合、Boss预警、过载压力画面；关闭浮字后看轮廓，再开启看危险是否仍清晰。怪物状态色必须由截图确认，不只查看赋值代码。
5. 对照 before/after 为相同393宽、相近波次/人数/能量状态。纯空场与满屏战斗不可用来宣称同等条件可读性提升。
6. 字体新增文案无缺字；运行资产/微信包体实际量测，不将“零新增PNG”当包体未增证明；纹理和字体加载失败状态须可定位。
7. 视觉审查、逻辑回归、桌面交互、真机触控/流畅度分别报告。当前此文件只交付方向与审查，不宣称新UI或微信真机通过。
