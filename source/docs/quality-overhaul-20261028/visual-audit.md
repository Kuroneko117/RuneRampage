## 比例、轮廓与敌我危险层级

玩家：原 `player_idle_02` 逻辑画布 80×88、可见主体约 76×69；runtime 高 112 不等于人物不透明高度 112。不能依据空白画布直接计算视觉体型。393 宽截图中主体约 35–40 像素高，身份仍可辨；不建议为“更醒目”直接放大到 1.5 倍，也不更换脸、帽、杖或现有运动语言。

普通敌人：slime 60、bat 62、imp/beetle 68 为画布高；精英 82×1.4≈115，Boss 82×2.4≈197。Boss 第一阶段可见体型受透明边距影响，明显小于 197；最终阶段又更充满画布。应以各帧 alpha 轮廓检查阶段变化，维持已有成长感，不能把所有阶段单独按可见包围盒拉成一样大。

轮廓读法：史莱姆是低矮圆团；蝙蝠是横展双翼；小恶魔是两角短肢；远程法师是竖向兜帽；精英守卫是宽肩躯干；甲虫用明确朝向与冲刺路径；巨像以体积和四肢负形读出。保留这些差异，不给所有敌人统一厚光圈。

最高层依次为：敌方预警与敌弹 → 玩家受击/生命危机 → 玩家主体与近身敌轮廓 → 敌人动作和身份标记 → 友方弹体 → 伤害数字 → 地面金币 → 场地纹样。现有 world sibling 顺序已将敌方危险置于玩家之上，可保留；数字虽在最上层，也须在视觉上低于危险线，必要时调父层或避让。

## 三个界面本轮决定

1. **主菜单**：角色与“开始游戏”构成中心焦点；工具入口减少厚实填色与鲜亮边框；标题保留中文大字，英文字标和页脚退后。保留已有功能，不因视觉整理删玩法或增加养成系统。
2. **商店**：采用强化后的原四卡构图。纵向四行只作为曾比较的备选；父会话补充用户之前否决纵向清单，因此不采纳。四卡用商品图标、收益、价格三层快速决策，刷新与强化明显弱于继续按钮，避免卡中再套信息卡。
3. **HUD**：保持 Cocos 原生 UI、现有操作方式及安全区适配；压缩说明，保留血量、倒计时和过载的清楚状态；先减少装饰和文字噪声，再评估是否需要改变战场范围。

具体 token、尺寸与状态见 [视觉方向](visual-direction.md)。
